- Trigger surface :: =push= restricted to =branches: [master]= plus =pull_request= (runs on every PR regardless of base/head branch) plus =workflow_dispatch= for manual gates. Every rage/* branch push would burn shared runner capacity (capacity=2 across the whole guest), so branch pushes rely on the PR trigger instead — matching the issue's "on pushes to master and on every pull request".
- Concurrency :: group =${{ github.workflow }}-${{ github.ref }}=, =cancel-in-progress: true= — a force of new commits on the same PR cancels the superseded run; different refs never cancel each other; master pushes are sequential by construction (one push per merge).

- Negative-check protocol :: first PR commit contains the workflow *with* one extra final step =name: negative proof (deliberately failing step)= / =run: false=, proving the workflow actually executes and gates (expected red). Second commit removes that step; the PR's final head shows the green run of the exact workflow. Both run records are preserved as evidence.
